# 登录来源校验与小红书入口去重设计

## 目标

修复源码启动回退到本地 React 构建时，登录 IPC 被误判为“不受信任来源”的问题；同时从统一登录页移除重复的小红书入口，只保留“小红书主页提取”页面内的登录入口。

## 根因

主窗口在未打包状态下会先访问 `http://localhost:3000`。开发服务器未运行时，它会回退到项目内的 `dist-react/index.html`。当前 IPC 安全策略在未打包状态下只信任开发服务器地址，因此本地回退页面可以显示，却不能调用 `open-login-window` 等 IPC。

小红书主页提取页面和统一登录页均调用 `openLoginWindow('xiaohongshu')`，共享同一个 `persist:xiaohongshu` 会话和凭据存储，两个入口没有功能差异。

## 设计

1. `isTrustedRendererUrl` 在开发和打包状态下都允许项目根目录中精确的 `dist-react/index.html`。
2. 继续拒绝其他本地文件、带查询参数或片段的本地地址、非开发服务器远程地址，以及缺少发送来源的 IPC。
3. 开发状态继续允许精确的 `http://localhost:3000` 来源。
4. 从 `CookieManager` 的平台标签配置中删除 `xiaohongshu`，不删除主进程中的小红书登录、Cookie 保存、状态检查和清理能力。
5. 小红书主页提取页面继续直接调用 `openLoginWindow('xiaohongshu')`；相关失效提示统一引导用户回到该页面。

## 测试

- 单元测试证明未打包状态下精确的本地入口可调用 IPC，其他本地文件仍被拒绝。
- 渲染层契约测试证明统一登录页不再包含小红书配置，而小红书主页提取仍保留登录调用。
- 运行完整 Node 测试、主进程与 preload 语法检查、React 生产构建。
- 以源码回退模式启动 Electron，确认主页面加载后 IPC 不再返回 `UNTRUSTED_RENDERER`。
- 重新生成并检查 Windows x64 安装包。

## 非目标

- 不改变 IPC 通道名称。
- 不放宽远程网页或登录网页对主进程 IPC 的访问。
- 不删除小红书登录会话、凭据或下载能力。
- 不修改旧的 `抖音下载器源码/` 目录。
